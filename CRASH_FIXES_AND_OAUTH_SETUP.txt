CRASHES IDENTIFIED AND FIXED
================================================================================

1. DUPLICATE API ENDPOINTS (RETROFIT CONFLICT)
----------------------------------------------
Problem:
- ApiService.java had two @GET("items") endpoints with same path but different signatures
- Retrofit cannot handle duplicate paths, causing runtime crashes

Original Code:
```java
@GET("items")
Call<List<Item>> getAllItems();

@GET("items")
Call<List<Item>> getFoundItems(@Header("Authorization") String authorization);
```

Fix Applied:
```java
@GET("items/public")  // Changed to different path
Call<List<Item>> getAllItems();

@GET("items")
Call<List<Item>> getFoundItems(@Header("Authorization") String authorization);
```

Files Modified: ApiService.java

2. RETROFITCLIENT NOT INITIALIZED (NULL CONTEXT CRASH)
-----------------------------------------------------
Problem:
- RetrofitClient.initialize(context) was never called
- applicationContext was null when making API calls
- Caused NullPointerException when creating AuthInterceptor and TokenManager

Fix Applied:
- Added RetrofitClient.initialize(this) in MainActivity.onCreate()
- Added null checks in RetrofitClient.getApiService()

Files Modified:
- MainActivity.java (added initialization)
- RetrofitClient.java (added null checks)

3. AUTHENTICATION REQUIRED FOR VIEWING ITEMS
-------------------------------------------
Problem:
- FoundItemsFragment required authentication to view items
- Users should see items without logging in first
- Caused crashes for unauthenticated users

Fix Applied:
- Modified FoundItemsFragment to use public getAllItems() endpoint
- No authentication required for viewing items
- Authentication only required for posting/contacting

Files Modified: FoundItemsFragment.java

4. EDGE-TO-EDGE DISPLAY SENSOR CONFLICTS
---------------------------------------
Problem:
- EdgeToEdge.enable(this) in SplashScreenActivity caused sensor registration failures
- "Proximity Gated Single Tap Gesture" sensor conflicts
- App crashed on startup due to sensor issues

Fix Applied:
- Wrapped EdgeToEdge.enable() in try-catch block
- Added error logging for sensor issues
- App continues running even if edge-to-edge fails

Files Modified: SplashScreenActivity.java

5. MISSING PARAMETER IN ADDITEM API CALL
---------------------------------------
Problem:
- PostItemFragment was calling addItem(newItem) with only 1 parameter
- ApiService.addItem() requires 2 parameters: authorization header and item

Fix Applied:
- Added TokenManager to get authorization header
- Modified API call to include both parameters: addItem(authToken, newItem)
- Added proper authentication validation

Files Modified: PostItemFragment.java

OAUTH2 CLIENT_ID AND CLIENT_SECRET SETUP
================================================================================

CURRENT STATUS:
Your RetrofitClient.java contains placeholder values:
```java
private static final String CLIENT_ID = "your-client-id";
private static final String CLIENT_SECRET = "your-client-secret";
```

WHERE TO GET CLIENT_ID AND CLIENT_SECRET:
==========================================

These values come from your BACKEND SERVER, not from Google or any external service.
Since you're building a custom Lost & Found app, you need to configure OAuth2
on your backend server.

BACKEND SETUP REQUIRED:
======================

1. SPRING BOOT OAUTH2 SETUP (If using Spring Boot):

   Add dependencies to your backend's pom.xml or build.gradle:
   ```xml
   <dependency>
       <groupId>org.springframework.boot</groupId>
       <artifactId>spring-boot-starter-oauth2-authorization-server</artifactId>
   </dependency>
   ```

2. CONFIGURE OAUTH2 CLIENT IN BACKEND:

   In your backend application.properties or application.yml:
   ```properties
   # OAuth2 Client Configuration
   spring.security.oauth2.client.registration.myapp.client-id=lost-found-mobile-app
   spring.security.oauth2.client.registration.myapp.client-secret=your-secret-key-here
   spring.security.oauth2.client.registration.myapp.authorization-grant-type=password
   spring.security.oauth2.client.registration.myapp.scope=read,write
   ```

3. CREATE OAUTH2 CLIENT IN DATABASE:

   Your backend should have a table for OAuth2 clients. Insert a record like:
   ```sql
   INSERT INTO oauth_client_details (
       client_id,
       client_secret,
       scope,
       authorized_grant_types,
       authorities,
       access_token_validity,
       refresh_token_validity
   ) VALUES (
       'lost-found-mobile-app',
       '{bcrypt}$2a$10$your-encoded-secret-here',
       'read,write',
       'password,refresh_token',
       'ROLE_CLIENT',
       3600,
       86400
   );
   ```

RECOMMENDED VALUES FOR YOUR APP:
===============================

For development/testing purposes, you can use:

CLIENT_ID: "lost-found-mobile-app"
CLIENT_SECRET: "lost-found-secret-2025"

UPDATE YOUR ANDROID APP:
========================

Replace the placeholder values in RetrofitClient.java:

```java
private static final String CLIENT_ID = "lost-found-mobile-app";
private static final String CLIENT_SECRET = "lost-found-secret-2025";
```

SECURITY CONSIDERATIONS:
=======================

1. PRODUCTION SETUP:
   - Use strong, randomly generated client secrets
   - Store secrets securely (consider using Android Keystore)
   - Use HTTPS in production (not HTTP)
   - Implement proper token expiration and refresh

2. CURRENT DEVELOPMENT SETUP:
   - Your BASE_URL uses HTTP: "http://192.168.18.61:8080/api/"
   - This is fine for local development
   - Change to HTTPS for production

3. CLIENT SECRET SECURITY:
   - Consider using PKCE (Proof Key for Code Exchange) for mobile apps
   - Store client secrets in Android's encrypted SharedPreferences
   - Implement certificate pinning for production

BACKEND API ENDPOINTS REQUIRED
================================================================================

Your Android app expects these endpoints on your backend server:

AUTHENTICATION ENDPOINTS:
- POST /api/oauth/token (for login)
- POST /api/oauth/token (for refresh token)
- POST /api/auth/register (for user registration)

ITEM ENDPOINTS:
- GET /api/items/public (public endpoint - no auth required)
- GET /api/items (authenticated endpoint)
- POST /api/items (create new item - requires auth)

USER ENDPOINTS:
- GET /api/users/me (get current user)
- PUT /api/users/me (update user)
- GET /api/users/{id} (get user by ID)
